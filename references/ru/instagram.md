# Instagram (Graph API, публикация контента)

Публикация в Instagram из self-hosted n8n через `graph.instagram.com` (Instagram API with
Instagram Login), токены Meta, хостинг картинок.

> Шаги интерфейса Meta-кабинета и версия API (`v23.0`) актуальны на момент написания —
> Meta периодически переименовывает пункты и поднимает версию. Сверяй с текущей документацией.

---

## IG-Р1 ✅ Доступ к Instagram API для своего аккаунта без App Review

**Контекст.** Нужно публиковать посты в собственный IG-аккаунт из n8n. Сервисов-посредников
(как master-приложение у облачных платформ) у self-hosted n8n нет.

**Решение** (✅ подтверждено в проде):

1. IG-аккаунт должен быть **профессиональным** (Business/Creator) и **открытым**.
2. developers.facebook.com → Создать приложение → use case **«Управление сообщениями и
   контентом в Instagram»** (INSTAGRAM_BUSINESS).
3. **Роли в приложении → Добавить людей → «Тестировщик Instagram»** (именно эта роль, не
   «Разработчик») → username IG-аккаунта. Приглашение для аккаунта владельца приложения
   подтверждается автоматически (instagram.com/accounts/manage_access/ → «Приглашения Для
   Тестировщиков»).
4. Сценарии использования → Настройка API для входа в Instagram → блок 1 «Add all required
   permissions» → блок 2 **«Добавить аккаунт»** (вход в IG + 2FA) → **«Сгенерировать маркер»**.
5. Токен long-lived (~60 дней), начинается с `IGAA...`. Работает и как `?access_token=`, и как
   заголовок `Authorization: Bearer` → в n8n хранить как credential **httpHeaderAuth**.

**Цикл публикации фото** (без поллинга, который нужен только видео/Reels):

```
POST https://graph.instagram.com/v23.0/me/media        (image_url, caption)  → {id: container_id}
POST https://graph.instagram.com/v23.0/me/media_publish (creation_id)        → {id: media_id}
GET  https://graph.instagram.com/v23.0/{media_id}?fields=id,permalink        → ссылка на пост
```

App Review не нужен, пока публикуем только в аккаунты с ролью в приложении. Продление токена:
`GET https://graph.instagram.com/refresh_access_token?grant_type=ig_refresh_token&access_token=<токен>`
(токен должен быть старше 24 ч). Удаление постов через API не поддерживается — только вручную.

Хост — **graph.instagram.com** (не graph.facebook.com): токен Instagram Login работает именно
там, Facebook-страница не нужна.

## IG-О1 ⚠️ «Недостаточно прав для роли разработчика» при привязке IG-аккаунта

**Симптом.** В Meta-кабинете, блок «Сгенерируйте маркеры доступа» → «Добавить аккаунт» → после
входа в Instagram попап с ошибкой «Недостаточно прав для роли разработчика».

**Причина.** IG-аккаунту не выдана роль **«Тестировщик Instagram»** в приложении. Роль
«Разработчик» (Facebook-профиль) — не то же самое и не помогает.

**Решение.** Роли в приложении → Добавить людей → «Тестировщик Instagram» (нижний пункт,
«Дополнительные роли») → username IG-аккаунта → для своего аккаунта приглашение
авто-подтверждается → повторить «Добавить аккаунт». Статус: ✅ воспроизведено и устранено.

## IG-О2 ⚠️ Ошибка 9004/2207052 «Не удалось скачать медиафайл» при создании контейнера

**Симптом.** `POST /me/media` →
`{"error":{"code":9004,"error_subcode":2207052,"message":"Only photo or video can be accepted as media type."}}`
— формулировка обманчивая, реальный текст в `error_user_msg`: «Не удалось извлечь медиафайл по
URI».

**Причина.** Робот Meta не смог скачать картинку по `image_url`. Часть CDN с anti-bot
(например `upload.wikimedia.org`) отдают ему отказ.

**Решение.** Использовать хостинг, с которого Meta скачивает без проблем (проверено: imgBB,
`i.ibb.co`). Формат — JPEG. Статус: ✅ воспроизведено и устранено.
