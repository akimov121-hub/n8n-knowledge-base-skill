# Подключение к n8n по API — как работать с n8n проще всего

**Главная рекомендация этого скилла.** Самый удобный, быстрый и предсказуемый способ
управлять n8n с помощью AI-ассистента (как это делаем мы) — **через REST API сервера n8n**, а
не кликами в UI. Ассистент сам читает воркфлоу, хирургически правит ноды, деплоит, проверяет
executions и находит ошибки — без ручного клацанья по канвасу.

> Почему именно так:
> - **Хирургическая правка.** Можно поменять одну ноду в JSON и задеплоить, не трогая
>   остальное.
> - **Полный цикл из терминала/скрипта.** Создание, активация, проверка прогонов,
>   диагностика ошибок — всё программно и воспроизводимо.
> - **Версионируемость.** Экспортированный `workflow.json` лежит в репозитории, видна история
>   через diff.
> - **AI-ассистент работает напрямую.** Дав ему API-ключ и домен, ты делегируешь ему всю
>   рутину по сборке и отладке.

Дисциплина деплоя (PUT затирает credentials, минимальные settings, проверка активности) —
в `rest-api-deploy.md`. Здесь — как вообще подключиться.

---

## Что нужно

- **Self-hosted n8n** (своя инсталляция на сервере/VPS). У n8n есть встроенный **Public REST
  API** — он и используется.
- Доступ в UI n8n с правами, позволяющими создать API-ключ.

---

## Шаг 1. Получить ключ Public REST API

1. В интерфейсе n8n: **Settings → n8n API → Create an API key**.
2. Скопировать ключ (показывается один раз). Это JWT с audience `public-api`.
3. Этот ключ передаётся в каждом запросе заголовком `X-N8N-API-KEY: <ключ>`, эндпоинты —
   `/api/v1/...`.

> Если пункта «n8n API» нет — Public API отключён в конфиге инстанса (`N8N_PUBLIC_API_DISABLED`).
> Включается администратором сервера.

## Шаг 2. Определить базовый URL

Это адрес твоего n8n, например `https://n8n.example.com`. Все вызовы идут к
`<BASE_URL>/api/v1/...`.

## Шаг 3. Хранить доступы в отдельном env-файле (не в коде!)

Завести файл `.n8n-api-key` (добавить в `.gitignore`) и держать в нём ключ и домен:

```bash
# .n8n-api-key
export N8N_API_KEY="<твой public-api JWT>"
export N8N_BASE_URL="https://n8n.example.com"
```

Тогда в любом скрипте/терминале: `source ./.n8n-api-key` — и ключ с доменом доступны как
переменные. AI-ассистенту достаточно указать на этот файл — он сам подставит значения, не
зная самого секрета в открытом виде в истории чата.

## Шаг 4. Проверить связь

```bash
source ./.n8n-api-key
curl -s -H "X-N8N-API-KEY: $N8N_API_KEY" \
  "$N8N_BASE_URL/api/v1/workflows?limit=5" | head
```

Вернулся JSON со списком воркфлоу — подключение работает. `401` — неверный ключ; `404` на
домене — неверный `BASE_URL` или Public API выключен.

## Ключевые эндпоинты Public API

| Действие | Запрос |
|---|---|
| Список воркфлоу (поиск по имени) | `GET /api/v1/workflows?limit=200` |
| Получить воркфлоу (актуальный JSON) | `GET /api/v1/workflows/{id}` |
| Создать воркфлоу | `POST /api/v1/workflows` |
| Обновить воркфлоу (полная замена нод!) | `PUT /api/v1/workflows/{id}` |
| Активировать / деактивировать | `POST /api/v1/workflows/{id}/activate` · `/deactivate` |
| Прогоны (диагностика ошибок) | `GET /api/v1/executions?workflowId={id}&limit=3` |
| Список credential'ов (узнать их id) | `GET /api/v1/credentials` |
| Теги | `GET/POST /api/v1/tags`, привязка `PUT /api/v1/workflows/{id}/tags` |

> ⚠️ Перед первым `PUT` обязательно прочитай `rest-api-deploy.md` (DEP-Р2): GET не отдаёт
> `credentials`, и PUT без них снесёт все привязки нод. Это главная грабля API-деплоя.

---

## Опционально: MCP-сервер n8n

В новых версиях n8n есть MCP-сервер (audience `mcp-server-api`, заголовок
`Authorization: Bearer <token>`, эндпоинт `/mcp-server/http`) — отдельный токен для
SDK/MCP-операций. Это альтернативный транспорт; базовый и универсальный путь — Public REST API
выше. Не путать два токена: REST-ключ не работает на MCP-эндпоинте и наоборот.

---

## Безопасность доступа

- API-ключ = полный доступ к воркфлоу и данным. Хранить как пароль, не коммитить, не
  вставлять в Sticky Notes.
- При компрометации — отозвать ключ в **Settings → n8n API** и создать новый.
- Домен и webhook-URL публично не светить.
